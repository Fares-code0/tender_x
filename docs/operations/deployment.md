# دليل النشر

> **الحالة: D0 فقط.** هذا الملف يغطي حاليًا **سحب الصور وتشغيلها**.
> النشر على خادم (D2) والتراجع والـrunbook (D4) تُضاف في مواضعها من
> `CLAUDE_CODE_PROMPT_Tender_Deployment.md`.

---

## 1) أين تعيش الصور

`ghcr.io/fares-code0/tender-api`

| الوسم | المعنى | متى يُستعمل |
| --- | --- | --- |
| `v2.1.0` | إصدار موسوم | **الإنتاج** — دائمًا وسم صريح |
| `sha-1f9e464` | نسخة مرتبطة بـcommit بعينه | تشخيص: أي شيفرة بالضبط تعمل الآن |

**لا يوجد وسم `latest` عمدًا.** خادم يسحب `latest` لا يمكن لأحد أن يقول ما الذي يعمل عليه، ولا أن يعيده إلى ما قبله بثقة.

---

## 2) كيف تُنشر الصور

عند دفع وسم `v*` يعمل [`release.yml`](../../.github/workflows/release.yml) تلقائيًا. وللوسوم القديمة (`v2.0.0`، `v2.1.0`) — لم تكن موجودة يوم أُنشئ الـworkflow فلا تُطلقه بأثر رجعي — يُستعمل التشغيل اليدوي:

```bash
gh workflow run release.yml -f tag=v2.1.0
```

**الترتيب داخل الـworkflow مقصود:** بناء ⇒ اختبار دخان (18 فحصًا داخل الحاوية) ⇒ دفع. صورة تفشل الدخان **لا تصل السجلّ إطلاقًا**، ثم تُسحب المنشورة على runner نظيف وتُشغَّل للتأكد من أن ما وصل السجلّ يعمل فعلًا.

---

## 3) سحب صورة وتشغيلها

السجلّ خاص، فيلزم الدخول أولًا برمز وصول شخصي له صلاحية `read:packages`:

```bash
echo "$GITHUB_TOKEN" | docker login ghcr.io -u <username> --password-stdin
```

ثم:

```bash
docker pull ghcr.io/fares-code0/tender-api:v2.1.0
```

التشغيل يحتاج قاعدة بيانات وسرًّا. **السرّ يُمرَّر وقت التشغيل ولا يُخبز في الصورة إطلاقًا** (H7.3)، ويجب أن يكون عشوائيًا ولا يقل عن 16 حرفًا وإلا رفض التطبيق الإقلاع (H0.1):

```bash
docker run -d --name tender_api -p 4000:4000 -e DATABASE_URL='postgresql://user:pass@host:5432/tender' -e JWT_SECRET="$(openssl rand -hex 32)" -e NODE_ENV=production ghcr.io/fares-code0/tender-api:v2.1.0
```

### التحقق من أنها تعمل

```bash
curl -fsS http://localhost:4000/livez
```

| المسار | المتوقع | ماذا يثبت |
| --- | --- | --- |
| `/livez` | `{"status":"live"}` | العملية حيّة (لا يلمس القاعدة) |
| `/readyz` | `{"status":"ready"}` | `SELECT 1` عبر Prisma نجح ⇒ القاعدة موصولة والمحرّك سليم |
| `/v1/tenders` | `401` | التطبيق يخدم مساراته فعلًا لا فحوص الصحة فقط |

`/readyz` يردّ **503** إن تعذّر الوصول للقاعدة — وهذا هو المسار الذي يجب أن يعتمده أي موازن أحمال، لا `/livez`.

## 4) المنظومة كاملة محليًا

للتشغيل من المصدر (قاعدة + هجرات + API):

```bash
JWT_SECRET=$(openssl rand -hex 32) docker compose up --build -d
```

ثم اختبار الدخان:

```bash
bash scripts/docker-smoke-test.sh
```

## 5) ما لا يغطيه هذا الملف بعد

| الموضوع | البند |
| --- | --- |
| الواجهة (`apps/web`) — غير محوّاة بعد | D1 |
| النشر على خادم، TLS، الأصل الواحد | D2 |
| النسخ الاحتياطي والاستعادة | D3 |
| التراجع، الـrunbook، المراقبة | D4 |

### ⚠️ فجوة مكتشَفة أثناء D0 (تُحسم في D2)

الصورة المنشورة **لا تصلح لتشغيل الهجرات**: أداة `prisma` تطويرية، و`pnpm --prod deploy` يستبعدها، فصورة التشغيل بلا مُهاجِر. محليًا تحلّ خدمة `migrate` المشكلة ببنائها من مرحلة `build`، لكن تلك المرحلة **غير منشورة** — فخادم لا يملك سياق البناء لا يستطيع تطبيق هجرة.

لهذا لا يلمس D0 الهجرات إطلاقًا: تحقّقه يقوم على `/readyz` وهو `SELECT 1` ينجح على قاعدة فارغة بلا حاجة إلى أي هجرة.

الحسم في D2 بين خيارين، ويحتاج قرارك:

1. **إدراج أداة prisma في صورة التشغيل** — صورة واحدة تكفي للتشغيل والهجرة، بزيادة في الحجم.
2. **نشر صورة ثانية للهجرات** من مرحلة `build` — صورة تشغيل تبقى نحيلة، مقابل صورة إضافية أضخم ووقت بناء أطول.
